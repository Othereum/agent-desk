# agent-desk 태스크 종료

CLI 경로, 기록 규칙, 문서 위치 기준은 `agent-desk:desk` 스킬을, knowledge 규칙은 `agent-desk:kn` 스킬을 따른다.

1. 대상 태스크를 확인한다. 지정이 없으면 `adesk where`의 `focus`를 쓴다.
2. 종료 결과를 정한다: 목표를 이뤘으면 `done`, 이루지 않고 그만두면 `cancelled`.
3. **마무리 기록**: state.md의 "현재 상태"에 최종 결과를 한두 줄로 적고(`put`), log.md에 종료 요약을 남긴다(`append`). 데스크 파일은 Edit하지 않는다(`agent-desk:desk` 스킬 "파일별 작성 규칙").
4. **저장소 문서 점검**: 이 태스크가 문서화된 시스템의 동작을 바꿨거나 새 문서 기준을 만족하는 시스템을 만들었는데, 저장소 문서에 반영되지 않았는지 확인한다.
   - 반영이 빠졌으면 사용자에게 알린다. 태스크 브랜치가 아직 머지되지 않았으면 그 브랜치에 반영을 제안하고, 이미 머지되었으면 문서 반영용 후속 태스크를 제안한다. 후속 태스크는 `new --related <이 태스크 id>`로 만들어 원래 태스크와 연결한다.
   - 종료 단계에서 저장소 문서를 직접 커밋하지 않는다.
5. **설계 문서 마무리**: `design_doc`이 있으면 최종 결과와 decisions.md의 마지막 상태를 반영해 갱신한다. Claude Docs 도구를 쓸 수 없는 세션이면 갱신이 필요하다는 점만 알린다.
6. **knowledge 추출**: decisions.md, log.md, state.md를 훑어 태스크가 끝나도 유효한 사실을 고른다. 이미 작업 중에 기록한 항목은 `kn list`로 확인해 중복을 피한다.
   - 고르는 기준: 다음에 이 코드를 다룰 사람이 모르면 시간을 잃거나 실수할 내용인가?
   - 함정, 원인, 방법(pitfall/finding/howto)은 항목 본문(`inline`)에 쓴다.
   - 설계 결정(decision)은 요약만 본문에 쓰고, `design_doc`이 있으면 `--location claude-docs:<url>`로 설계 문서를 가리킨다. `--paths`는 그 설계가 다루는 코드 범위로 정한다. 나중에 그 코드를 건드릴 때 설계 문서로 가는 길이 된다.
   - 저장소 문서에 이미 반영된 내용은 knowledge로 중복 기록하지 않는다.
   - 후보를 사용자에게 **한 번에 목록으로** 제안하고, 승인한 항목만 기록한다.
   - 옮긴 결정에는 decisions.md의 해당 항목 머리 줄 끝(괄호 뒤)에 `→ K0012`처럼 knowledge ID를 덧붙인다(사본을 고쳐 `put`).
7. 종료한다: `adesk close <id> done|cancelled --note "한 줄 요약"`
   - 하위 태스크를 종료하면 상위 태스크의 state.md "현재 상태"에 결과를 한 줄 반영한다.
   - 포커스 태스크를 종료하면 포커스는 없어진다. 상위 태스크 등 이어서 할 태스크가 있으면 `focus <id>`로 옮길지 사용자에게 묻는다.
   - 상위 태스크를 종료할 때 열린 하위 태스크가 남아 있으면 출력에 `warning`이 나온다. 하위 태스크를 먼저 정리할지 사용자에게 확인한다.
8. 아카이브 경로, 새로 기록한 knowledge ID, 남은 후속 조치(문서 반영 등)를 짧게 알린다. 다시 열 때는 `reopen <id>`를 쓰면 된다는 점도 함께 알린다.
