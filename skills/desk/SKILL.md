# agent-desk

에이전트가 태스크 단위의 현황, 결정, 로그를 세션을 넘어 이어가기 위한 개인용 기록 공간(데스크) 및 도구다.

아래 상황에서는 이 스킬의 base directory에 있는 절차 파일을 읽고 따른다: `new.md`(태스크 생성), `close.md`(종료·취소, 삭제·복원), `init.md`(프로젝트 등록), `subagents.md`(서브에이전트에 일을 맡길 때).

## 용어

사용자와 에이전트가 같은 이름으로 부른다. 짧게 부르고, 문맥으로 해석하고, 모호하면 한 줄로 되묻는다. 사용자에게 말하거나 기록할 때도 이 이름을 쓴다.

| 이름 | 가리키는 것 |
|---|---|
| 데스크 | agent-desk가 관리하는 기록 공간(프로젝트별 태스크 기록). "데스크에 남겨줘", "데스크 점검해줘" |
| 프로젝트 | 등록한 저장소 |
| 태스크 기록 | 태스크 하나의 현황·결정·로그 |
| 현황 | state.md. "상태"는 태스크 상태에만 쓴다 |
| 태스크 상태 | 예정 `todo`(만들어 두고 착수 전), 진행 중 `in_progress`, 보류 `on_hold`(착수했다가 멈춤·기다림), 완료 `done`, 취소 `cancelled`(이루지 않고 종료). 앞의 셋이 **열린 태스크**, 뒤의 둘이 **종료된 태스크**(아카이브) |
| 결정 | decisions.md의 항목(D번호) |
| 로그 | log.md |
| 첨부파일 | 태스크 폴더의 `files/`에 붙여 둔 파일 |
| 상위·하위 태스크 | parent, 그 아래 태스크 |
| 브랜치 연결 | 이 태스크의 작업(코드 변경)이 그 브랜치에서 이루어진다는 기록. 그 브랜치에서는 이 태스크가 기본 후보가 된다. 한 브랜치에 여러 태스크, 한 태스크에 여러 브랜치를 연결할 수 있다. 공용 브랜치는 연결하지 않는다 |
| 포커스 | 이 세션이 작업하는 태스크. 사용자의 요청으로 정한다(`adesk focus`). 세션마다 따로 있고 다른 세션·PC와 공유하지 않는다. 기록은 포커스 태스크에 한다 |
| 아카이브 | 종료된 태스크를 옮겨 두는 곳 |
| 휴지통으로 옮기기 / 영구 삭제 | 태스크 삭제는 휴지통(`trash/`)으로 옮기기이고 되살릴 수 있다. 영구 삭제는 휴지통의 태스크를 지운다 |
| 데스크 점검 | `adesk doctor` |

## CLI

`adesk`로 실행한다. Claude Code가 플러그인 `bin/`을 셸 도구의 PATH에 넣고, Bash는 `bin/adesk`, PowerShell·cmd는 `bin/adesk.cmd`를 쓴다. `adesk`를 찾지 못하면 `adesk` 대신 이 스킬의 base directory 기준 `../../bin/desk.py`를 `python`으로 실행한다.

```
# 조회
adesk where                             # 프로젝트, 이 세션의 포커스(focus), 이 브랜치의 태스크 목록(branch_tasks)
adesk list [--all]                      # 태스크 목록 (--all: 아카이브 포함)
adesk list --deleted                    # 휴지통의 태스크 목록
adesk show <id>                         # 태스크 기록을 텍스트로 출력. 포커스·상태를 바꾸지 않고, 종료·휴지통 태스크도 읽는다

# 포커스
adesk focus <id>                        # 이 세션의 포커스를 정하고 기록을 텍스트로 출력 (todo면 진행 중으로)
adesk focus --clear                     # 이 세션의 포커스 해제

# 생성
# new는 예정(todo) 태스크의 기록만 만든다. 포커스·착수는 focus가 한다
adesk new --title "제목" --slug login   # ID는 <yymmdd>-<slug>. 브랜치 없는 태스크
adesk new --title "제목" --slug login --branch <B>   # 브랜치 B에 연결
adesk new --title "제목" --slug x --parent <id>   # 상위 태스크 지정

# 기록 쓰기
adesk put <데스크 파일> --file <파일|-> [--verified]   # 본문 교체 (frontmatter는 현재 값 유지)
adesk append <데스크 파일> --file <파일|->   # 끝에 덧붙이기 (decisions.md의 새 결정)
adesk log <id> --file <파일|->          # log.md에 항목 추가 (시각 제목은 CLI가 붙인다)

# 첨부파일 (files/, 아래 "첨부파일")
adesk files <id>                        # 첨부파일 목록
adesk files <id> add <파일...> [--replace] [--large]   # 첨부 (같은 이름은 --replace로 교체)
adesk files <id> rm <이름...>           # 첨부파일 삭제 (되살릴 수 없음, 사용자가 요청할 때만)

# 속성·관계 (frontmatter)
adesk set <id> [--title "제목"] [--parent P | --no-parent]   # 제목, 상위 태스크 변경
adesk link <id> [--branch B]            # 태스크에 브랜치 추가
adesk unlink <id> [--branch B]          # 브랜치 연결 해제(버린 브랜치 정리)

# 상태·종료·삭제
adesk status <id> todo|in_progress|on_hold
adesk close <id> done|cancelled [--note "..."]
adesk reopen <id>
adesk delete <id>                       # 휴지통으로 옮기기 (열린·종료된 태스크 모두)
adesk restore <id>                      # 휴지통에서 되살리기 (상태에 따라 tasks/ 또는 archive/로)
adesk delete <id> --purge               # 휴지통의 태스크를 영구 삭제

# 점검·관리
adesk doctor [--apply]                  # 데스크 점검: 충돌 사본·frontmatter 오류·방치된 태스크 (아래 "데스크 점검")
adesk index                             # 태스크 index.md 재생성
adesk migrate [--dry-run]               # 데이터 폴더를 현재 스키마로 변환
```
`--project KEY`와 `--cwd DIR`은 하위 명령 **앞에** 둔다. 출력은 JSON이다(`focus`·`show`는 태스크 기록 텍스트).

ID 생성, 브랜치 연결, 상태 전환, 아카이브·휴지통 이동은 반드시 CLI로 한다. 폴더를 직접 만들거나 옮기거나 지우지 않는다.

**frontmatter는 CLI가 쓰고, 글(본문, log.md, decisions.md)은 에이전트가 쓴다.** frontmatter 값은 전용 명령으로 바꾼다: 태스크의 제목·상위 태스크는 `set`, 상태는 `status`·`close`, 브랜치는 `link`·`unlink`. 제목 변경은 오타 수정용이고, 일의 범위가 바뀌면 새 태스크로 만든다. `updated`는 CLI가 태스크 파일을 쓸 때 자동으로 바뀐다.

## 저장 구조

```
<root>/projects/<KEY>/project.toml        # 프로젝트 설정 (remotes, paths, shared_branches)
<root>/projects/<KEY>/index.md            # 자동 생성, 직접 수정 금지
<root>/projects/<KEY>/tasks/<id>/state.md       # 현황: 덮어씀
<root>/projects/<KEY>/tasks/<id>/decisions.md   # 결정: 항목 추가
<root>/projects/<KEY>/tasks/<id>/log.md         # 로그: 덧붙이기만
<root>/projects/<KEY>/tasks/<id>/files/         # 첨부파일: adesk files로만
<root>/projects/<KEY>/archive/<id>/...    # 종료된 태스크
<root>/projects/<KEY>/trash/<id>/...      # 휴지통 (목록·주입·브랜치 매칭에서 빠짐)
```

## 태스크 생성 기준

- 사용자가 지시하면 만든다.
- 사용자가 **목표가 있는 새 일**(기능 구현, 버그 수정, 리팩터링처럼 세션을 넘겨 이어질 일)을 시작하려 하면, 착수 전에 태스크로 기록할지 한 줄로 묻는다. 이 세션에서 새 브랜치를 만들었을 때도 같다.
- 묻지 않는 것: 잠깐의 질문, 조사, 일회성 수정, 이미 있는 태스크 범위의 일. 이런 것마다 태스크를 만들면 기록이 소음이 된다. 사용자가 거절한 일은 그 세션에서 다시 묻지 않는다.
- 만들 때 사용자가 정한 목표와 범위를 현황에 적는다.
- 만든 태스크는 예정(`todo`)이다. 지금 착수할 일이면 만든 뒤 `focus`로 포커스하고(진행 중이 된다), 나중에 할 일이면 그대로 둔다.
- 만들기로 하면 `new.md` 절차를 따른다. 프로젝트가 등록되지 않았으면 `init.md` 절차를 먼저 안내한다.

## 포커스 (이 세션의 태스크)

세션에서 무슨 일을 할지는 사용자가 정한다. SessionStart는 태스크 기록을 넣지 않고 후보만 알린다(이 브랜치에 연결된 태스크, 없으면 열린 태스크 전체). 에이전트는 사용자의 요청을 보고 `adesk focus <id>`로 포커스를 정하고, 출력된 기록(현황·결정 목록·상위 태스크)을 읽고 시작한다.

- **이 브랜치에 연결된 태스크가 기본값이다.** 하나뿐이면 첫 요청이 이 브랜치의 작업일 때("이어서 하자", 코드 수정, 버그 조사) 묻지 않고 포커스한다. 여럿이면 요청에 맞는 것으로 포커스하고, 애매하면 묻는다. 요청이 다른 태스크를 가리키거나 관련이 애매하면 묻는다.
- 브랜치에 연결된 태스크가 없으면 기본값이 없다. 요청이 후보 중 하나를 분명히 가리키면 포커스하고, 아니면 묻는다.
- 태스크와 무관한 세션(가벼운 질문 등)이면 포커스하지 않는다. **포커스 전에는 기록하지 않는다.** 기록할 일이 생기면 어느 태스크에 남길지 묻는다.
- 다른 태스크의 기록을 읽기만 할 때(현황을 묻거나 참고할 때)는 포커스를 옮기지 않고 `adesk show <id>`로 읽는다.
- `new`는 포커스를 바꾸지 않는다. 만든 태스크에 착수하면 `focus`로 포커스한다.
- 포커스는 이 세션에서만 유지된다. 압축·재개 뒤에는 SessionStart가 그 기록을 다시 주입하고, `/clear`는 새 세션이라 다시 고른다. 다른 세션·다른 PC와 공유되지 않는다.
- 다른 태스크로 넘어갈 때는 사용자에게 확인하고 `focus <id>`로 옮긴다. 포커스 태스크를 닫으면(`close`) 포커스는 없어진다. 상위 태스크로 이어 갈지 사용자에게 묻는다.
- 세션 중에 저장소나 브랜치가 바뀌면 "작업 위치가 바뀌었다" 블록으로 새 위치의 후보가 표시된다(worktree 진입·이탈은 즉시, 터미널에서 바꾼 브랜치는 다음 프롬프트에서). 사용자의 일이 그 브랜치의 태스크로 바뀌었으면 `focus`로 옮긴다. 직접 Bash로 브랜치를 바꿨다면 주입을 기다리지 말고 `where`로 확인한다.
- "이 세션의 포커스가 바뀌었다" 안내가 나왔는데 직접 바꾼 것이 아니면, 서브에이전트가 바꾼 것이다. 사용자에게 알리고 `focus`로 바로잡는다.

## 상위 태스크

- **상위 태스크(`parent`)**: 여러 브랜치로 나뉘어 진행되는 큰 흐름(예: 여러 모듈의 독립화)을 묶는다. 상위 태스크는 보통 브랜치 없는 태스크로 만들고, 각 브랜치 태스크를 `--parent`로 그 아래에 둔다. 계층은 한 단계만 허용된다. 나중에 바꿀 때는 `set <id> --parent <P>`·`--no-parent`.
  - 하위 태스크 세션에는 상위 태스크의 state.md 전문과 결정 제목이 함께 주입된다. 이 세션의 할 일은 하위 태스크 state.md를 따른다. **상위 태스크의 유효한 결정을 따른다.** 어긋나는 결정이 필요하면 사용자에게 확인한다.
  - 흐름 전체에 걸친 결정은 상위 태스크의 decisions.md에, 이 브랜치에만 해당하는 결정은 하위 태스크의 decisions.md에 기록한다.
  - 상위 태스크의 state.md는 흐름 전체의 목표와 하위 태스크에서 나온 결과를 짧게 유지한다. 하위 태스크 목록은 `parent`로 `list`에서 알 수 있으므로 state.md에 나열하지 않는다. 하위 태스크에서 단계가 끝나거나 하위 태스크가 종료되면 상위 태스크의 "현재 상태"에 결과를 한 줄 반영한다.

## 파일별 작성 규칙

데스크 파일은 Edit/Write 도구로 고치지 않는다(hook이 거부한다). rewind(Restore code)는 Edit/Write로 바꾼 것만 되돌리고 CLI로 바꾼 것은 남겨서, 섞어 쓰면 데스크가 어긋난다. 내용은 scratchpad(없으면 작업 디렉터리 밖 임시 폴더)에서 만들고 CLI로 반영한다. sed 등으로 직접 고치지 않는다(조용히 실패할 수 있다).
- 고치기(state.md, decisions.md의 기존 항목): 데스크 파일을 scratchpad에 `cp`로 복사하고, 사본을 Read·Edit한 뒤 `adesk put <데스크 파일> --file <사본>`. put은 frontmatter 전체를 현재 파일 값으로 유지하므로(사본에는 본문만 있어도 된다) 사본의 frontmatter를 고쳐도 반영되지 않는다. 사본과 달랐던 키는 출력의 `kept`로 알린다.
- 덧붙이기(decisions.md의 새 결정): 덧붙일 부분만 scratchpad 파일에 Write하고 `adesk append <데스크 파일> --file <파일>`. 짧으면 `--file -`와 heredoc으로 표준 입력에 넘겨도 된다.
- 로그 항목(log.md): bullet 본문만 `adesk log <id> --file <파일|->`로 넘긴다. `## YYYY-MM-DD HH:MM` 제목은 CLI가 현재 시각으로 붙인다.
- 데스크 파일 경로는 절대 경로나 데이터 폴더 기준 상대 경로(`projects/<KEY>/tasks/<id>/state.md`)로 쓴다. 새 파일은 만들지 않는다(태스크 파일은 `new`가, 첨부파일은 `files add`가 만든다).

기록 파일은 UTF-8(BOM 없음), LF로 저장한다(put·append가 BOM과 CRLF를 정리한다). 첨부파일은 받은 그대로 저장한다.

기록에서 다른 태스크는 전체 ID로(`261016-login`, 줄이지 않는다), 그 태스크의 결정은 `<id>#D<n>`으로, 같은 태스크의 결정은 `D<n>`으로 쓴다. 다른 프로젝트면 앞에 `<KEY>/`를 붙인다(`proj/261016-login#D2`).

CLI 인자로 넘기는 값은 CLI가 따옴표를 붙여 쓰니 그대로 넘긴다. 현재 파일의 frontmatter를 읽을 수 없을 때만 put이 사본의 frontmatter를 쓴다(고치는 경우). 이때는 맨 앞 열의 `key: 값`과 한 줄 목록(`[a, "b, c"]`)으로 쓰고, `#`나 `: `가 들어간 값은 따옴표로 감싼다.

### state.md (현황, 덮어씀)
- 세션 시작 시 이것만 읽어도 이어서 작업할 수 있게 쓴다. **60줄 이내**를 유지하고, 넘으면 지난 내용을 log.md로 옮긴다.
- 섹션: 목표 / 현재 상태 / 다음 할 일 / 미해결 질문 / 핵심 파일(`경로:줄 — 역할`) / 링크.
- 링크 섹션에는 이슈, PR, 외부 문서 링크, 설계 문서 등을 둔다. 줄 수를 줄일 때도 log.md로 옮기지 않는다.
- 내용을 코드와 대조해 확인했다면 `put --verified`로 반영한다(`verified` 갱신).

### decisions.md (결정, 항목 추가)
- 사용자와 방향을 확정한 **즉시** 기록한다. 나중으로 미루지 않는다.
- 설계 방향을 정하는 결정만 남긴다. 사용자가 결과를 보고 고르는 취향 수준의 선택(모양, 문구, 배치)은 결정으로 남기지 않는다.
- 형식: `## Dn. 제목  (YYYY-MM-DD, 유효)` 아래에 결정 / 이유 / 기각한 대안 / 영향 범위. 세션 주입이 이 머리 줄로 결정 목록을 만든다. put·append가 형식이 어긋나거나 번호가 빠지거나 겹치면 출력의 `warnings`로 알리니 고친다.
- 결정이 바뀌면 기존 항목을 지우지 않는다. 새 항목을 추가하고 **기존 항목의 상태도 바꾼다**. 주입되는 결정 목록에서 낡은 결정을 알아보는 곳은 기존 항목의 머리 줄이다.
  - 전체가 바뀌면 `대체됨 → Dm`, 일부만 바뀌면 `일부 대체됨 → Dm`. 여러 결정이 일부씩 바꾸면 `일부 대체됨 → Dm, Dk`로 늘리고, 나중에 남은 부분까지 바뀌면 `대체됨 → Dk`로 바꾼다.
  - 새 항목의 상태는 `유효`이고, 어느 결정의 어느 부분을 바꾸는지는 결정 본문에 적는다(`D21의 창 수준 모드를 없애고 …`).
  - 새 항목 추가와 기존 항목의 상태 변경은 사본 하나에서 함께 고쳐 put으로 반영한다.
- 기각한 대안과 그 이유를 꼭 남긴다. 같은 논의를 반복하지 않게 하는 핵심 정보다.

### log.md (히스토리, 덧붙이기만)
- `adesk log`로 짧은 bullet을 넘기면 CLI가 `## YYYY-MM-DD HH:MM` 제목 아래에 덧붙인다. 기존 항목은 수정하지 않는다.
- 무엇을 했는지보다 **무엇을 알아냈는지**(원인, 확인한 사실, 막힌 지점)를 중심으로 쓴다.

### 첨부파일 (files/)
- 첨부파일의 내용은 주입되지 않고 이름만 표시된다.
- scratchpad에서 만들어 `adesk files <id> add`로 첨부한다. 무엇인지 드러나는 이름을 붙인다. 고칠 때도 scratchpad에서 고쳐 `add --replace`로 바꾼다(put·append, Edit/Write는 쓰지 않는다).
- 10MB를 넘는 파일은 거부된다. 데이터 폴더가 동기화될 수 있으니 사용자에게 확인한 뒤에만 `--large`로 첨부한다.
- 삭제(`rm`)는 휴지통 없이 바로 지운다. 사용자가 요청할 때만 하고, 지운 첨부파일을 가리키던 문장도 고친다.

## 갱신 시점

- 결정을 확정했을 때: decisions.md에 즉시 기록.
- 함정이나 원인을 밝혀냈을 때: log.md에 기록.
- 의미 있는 단계가 끝났을 때(원인 규명, 구현 완료, 방향 전환): state.md 갱신 + log.md 항목 추가.
- 사용자가 태스크를 마무리하거나 세션을 정리하려 할 때: state.md의 "다음 할 일"이 최신인지 확인.
- 컨텍스트 압축 직후(세션 컨텍스트에 압축 안내가 있을 때): 빠진 내용을 기록.
- 사용자가 지시하고 바로 확인하는 자잘한 수정(모양·문구·배치 조정, 시도 후 되돌림)은 변경마다 기록하지 않는다. 묶음이 끝날 때(커밋, 세션 정리) state.md 갱신과 log.md 한 항목으로 남기고, 다음에도 쓸 만한 원인·함정만 적는다.
- 갱신은 짧게 하고, 사용자에게는 "agent-desk 갱신" 정도로 한 줄만 알린다.

## 기록하지 않는 것

태스크 기록에는 그 태스크의 맥락(목표, 진행, 결정, 알아낸 것)만 둔다. 태스크가 끝나도 유효한 사실, 사용자와 일하는 방식, 시스템의 현재 상태를 설명하는 문서는 데스크 밖에 둔다. 어디에 둘지는 Claude Code와 프로젝트 지침을 따른다.

## 데스크 밖에 쓸 때

데스크는 저장소 밖에 있는 이 사용자의 로컬 데이터다. 저장소의 코드·테스트·문서·주석·커밋 메시지·PR에는 태스크 ID, 결정 번호(D…), 데스크 경로를 쓰지 않는다. 다른 사람이나 다른 PC에서는 가리키는 곳이 없다. 근거가 필요하면 그 자리에 풀어 쓴다.

## 읽을 때의 태도

- 기록은 **확인할 출발점**이지 사실이 아니다. `verified` 날짜가 오래되었거나 코드와 어긋나면 코드를 우선하고 기록을 고친다.
- log.md는 필요할 때만 검색해서 읽는다. 통째로 읽지 않는다.
- 기존 설계를 바꾸거나 되돌리자고 제안하기 전, 그리고 기존 설계나 동작의 이유·기각한 대안·배경을 묻거나 설명하기 전에는 코드와 문서만 보고 답하지 않는다. 종료된 태스크를 포함해 decisions.md에서 이전 결정과 기각한 대안을 찾는다. `adesk where`의 `project_dir` 아래 `tasks/`와 `archive/`의 decisions.md를 검색한다. 찾아도 없을 때만 기록이 없다고 말한다.
- 세션 컨텍스트에 동기화 충돌 사본 경고가 있으면 사용자에게 알리고 병합 여부를 확인한다.

## 종료와 재개

멈출 때는 `status <id> on_hold`, 다시 시작할 때는 `status <id> in_progress`를 쓴다. 종료·취소와 태스크 삭제·복원은 `close.md`를 따른다.

## 데스크 점검

`adesk doctor`는 동기화 충돌 사본, frontmatter 오류, 로컬에서 사라진 브랜치에 연결된 태스크, 30일 넘게 갱신되지 않은 태스크, 휴지통에 30일 넘게 있는 태스크를 찾는다. 기록은 바꾸지 않는다.
- 사용자가 요청하면 실행하고 결과를 요약해 보여 준다. 고칠 것은 제안하고, 종료·연결 해제·영구 삭제는 사용자가 동의할 때만 한다.
- `--apply`는 이전 버전이 남긴 파일(프로젝트 공용 포커스 파일)을 지운다. 사용자가 동의할 때만 실행한다.
