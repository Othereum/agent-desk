# agent-desk

데스크는 태스크 단위로 일의 맥락(현황, 결정, 알아낸 것)을 남겨 다음 세션에서 이어갈 수 있도록 하는 Markdown 폴더다.

## 구조

저장소의 데스크 폴더는 `git config agent-desk.dir`에 등록된다. 등록하지 않은 저장소면 사용자가 요청할 때 폴더 위치를 물어 만들고 등록한다.

```
<데스크 폴더>/<id>/state.md       # 현황: 이것만 읽어도 이어서 할 수 있게, 60줄 이내
                  decisions.md   # 결정
                  log.md         # 알아낸 것(원인, 확인한 사실, 막힌 지점), 덧붙이기만
                  files/         # 첨부파일(근거 자료)
```

- ID는 `<yymmdd>-<slug>`. 템플릿은 이 스킬의 base directory 기준 `../../templates/ko/`.
- state.md frontmatter는 세션 시작 목록이 읽는다: `title`, `status`(`todo`·`in_progress`·`on_hold`가 열린 태스크, `done`·`cancelled`가 종료), `parent`(상위 태스크 ID, 한 단계만), `branches`(`[a, b]`, 이 일의 코드 변경이 이루어지는 브랜치. 공용 브랜치는 넣지 않는다). 태스크 폴더에는 위 파일만 둔다.

## 규칙

- **태스크는 사용자가 정한다.** 지시하면 만들고, 세션을 넘겨 이어질 새 일을 시작하려 하면 기록할지 한 줄로 묻는다. 잠깐의 질문·조사·일회성 수정에는 묻지 않는다. 세션에서 어느 태스크를 할지도 사용자의 요청으로 정하고, 애매하면 묻는다. 정해지면 그 태스크의 state.md를 읽고 시작한다.
- **다음 세션이 이어 갈 수 있게 유지한다.** 의미 있는 단계가 끝나거나 세션을 정리할 때 state.md를 최신으로 맞춘다.
- **결정은 확정한 즉시 남긴다.** `## Dn. 제목  (YYYY-MM-DD, 유효)` 아래에 결정 / 이유 / 기각한 대안 / 영향 범위. 기각한 대안과 이유가 같은 논의의 반복을 막는 핵심이다. 바뀐 결정은 지우지 않고 새 항목을 추가한 뒤 기존 항목의 머리 줄 상태를 `대체됨 → Dm`(일부면 `일부 대체됨 → Dm`)으로 바꾼다. 취향 수준의 선택은 결정으로 남기지 않는다.
- **상위 태스크의 유효한 결정을 따른다.** 어긋나야 하면 사용자에게 확인한다. 흐름 전체에 걸친 결정과 결과는 상위 태스크에 남긴다.
- **기록은 확인할 출발점이다.** 코드와 어긋나면 코드를 우선하고 기록을 고친다. 기존 설계를 바꾸자고 제안하거나 이유를 설명하기 전에는 종료된 태스크까지 decisions.md에서 이전 결정과 기각한 대안을 찾는다.
- **저장소 산출물에는 데스크를 가리키지 않는다.** 코드·문서·커밋 메시지·PR에 태스크 ID, 결정 번호, 데스크 경로를 쓰지 않고 근거를 풀어 쓴다. 데스크는 이 사용자만 보는 데이터다.
- **기록을 지우는 것은 사용자가 요청할 때만** 한다(태스크 폴더, 결정, 첨부파일). 세션 시작 블록의 경고(읽을 수 없는 state.md, 동기화 충돌 사본)는 사용자에게 알린다.
- 태스크의 맥락이 아닌 것(태스크가 끝나도 유효한 사실, 일하는 방식)은 데스크 밖에 둔다.
- 기록했으면 사용자에게 "agent-desk 갱신" 정도로 한 줄만 알린다.
