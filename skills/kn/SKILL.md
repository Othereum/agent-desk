# agent-desk knowledge

태스크가 끝나도 계속 유효한 **코드베이스와 시스템에 대한 사실**을 항목 단위로 쌓고, 관련 있을 때만 꺼내 쓰는 공간이다.

CLI 경로는 `agent-desk:desk` 스킬의 CLI 항목을 따른다.

## 무엇을 어디에 두는가

| 내용 | 위치 |
|---|---|
| 사용자와 일하는 방식 (선호, 규칙, 교정) | 에이전트 메모리. knowledge에 넣지 않는다. |
| 이 태스크에만 해당하는 현황과 결정 | 태스크 기록 (현황·결정·로그) |
| **태스크가 끝나도 유효한 코드·시스템에 관한 사실** | **knowledge** |

- 프로젝트 항목(`K0001`…): 특정 저장소의 코드에 관한 사실. `--paths`로 관련 파일을 지정한다.
- 전역 항목(`G0001`…, `--global`): 프로젝트를 가리지 않는 사실 (도구, 엔진, OS, 셸 등). `--tags`로만 매칭한다.

종류(`--kind`):
- `decision`: 설계 결정과 그 이유, 기각한 대안
- `pitfall`: "여기서 X를 하면 Y가 깨진다". 분량 대비 가치가 가장 크므로 놓치지 않는다.
- `finding`: 조사로 밝혀낸 동작 방식이나 원인
- `howto`: 반복될 절차

## 조회

- 시스템을 조사하거나 수정하기 **전에** 검색한다.
  ```
  adesk kn search <검색어...>              # 제목·태그·경로·본문 검색 (전역 포함)
  adesk kn search --path <파일 경로>        # 그 파일에 해당하는 항목 (파일 하나)
  adesk kn show <id...>                   # 항목 본문 전체
  adesk kn list                         # 전체 목록
  ```
  공백이 든 검색어(`"플러그인 업데이트 버전"`)는 구절 그대로와 단어별로 함께 찾고, 구절이 그대로 맞는 항목이 앞에 온다. 단어 끝의 조사(을·는·에서 등)는 떼고 찾는다.
- **자동 주입**: 파일을 Read/Edit/Write하면 그 경로에 해당하는 프로젝트 항목이 `[agent-desk knowledge]` 블록으로 자동 주입된다(세션당 항목별 한 번, 컨텍스트 압축 뒤에는 다시 주입). 주입된 항목 중 지금 태스크에 영향을 주는 것은 수정하기 전에 본문을 읽고 반영한다. 전역 항목은 경로가 없으므로 자동 주입되지 않는다. 필요하면 검색한다.
- 결과의 `summary`로 관련성을 판단하고, 필요한 항목만 `kn show <id>`로 보거나 `file`을 Read로 읽는다. `location`이 `repo:`나 `claude-docs:`이면 그 위치에 본문이 있다.
- knowledge는 **확인할 출발점**이다. `status`가 `stale`이거나 `verified`가 오래되었으면 코드와 대조한다. 대조해서 맞으면 `kn verify <id>`, 틀리면 아래 "고치기"를 따른다.

## 기록

**발견한 즉시 제안한다.** 함정, 원인, 설계 결정을 확정한 순간 사용자에게 한 줄로 기록을 제안한다. 종료 시점까지 미루면 맥락이 압축되어 세부 내용을 잃는다. 사용자가 승인한 항목만 기록한다.

```
adesk kn add --kind pitfall --title "한 문장 제목" \
  --paths "src/auth/**,src/**/SessionCache*.cs" --tags "auth,session" --slug session-cache-reload
```
본문은 생성된 `file`을 scratchpad에 복사해 쓰고 `adesk put <file> --file <사본>`으로 반영한다(데스크 파일은 Edit하지 않는다, `agent-desk:desk` 스킬 "파일별 작성 규칙"). 짧은 본문은 `--body`로 넘겨도 된다. 출처 태스크(`sources`)는 이 세션의 포커스 태스크로 자동 기록된다. 서브에이전트나 다른 태스크의 일이면 `--sources <id>`를 명시한다.

본문 규칙:
- **사실 하나만** 담는다. 둘 이상이면 항목을 나눈다.
- **15줄 이내**. 근거가 되는 코드 위치(`경로:줄`)를 반드시 포함한다. 근거 없는 추측은 기록하지 않는다.
- 커밋 해시는 적지 않는다(rebase로 바뀐다).
- 긴 내용은 `agent-desk:desk` 스킬의 "문서 위치 기준"에 따라 태스크 설계는 Claude Docs, 시스템의 현재 상태는 저장소 문서에 두고, 본문에는 요약만 쓴 뒤 `--location`으로 가리킨다. 저장소 문서에 이미 있는 내용은 중복 기록하지 않는다.
- `--paths`는 저장소 루트 기준 glob이다. 너무 넓게(`**`) 잡지 않는다. 나중에 해당 파일을 다룰 때 이 항목이 떠야 하는 범위로 정한다.

## 고치기

- 내용이 틀렸거나 바뀌었으면 **기존 항목을 지우지 않는다.** 바른 사실이 있으면 새 항목을 추가하고 `kn supersede <old> --by <new>`로 대체한다.
- 코드가 바뀌어 다시 확인해야 하는데 지금 확인할 수 없으면 `kn stale <id> --reason "<이유>"`로 표시한다.
- 대체할 사실 없이 틀렸거나 더 이상 의미가 없으면 `kn retire <id> --reason "<이유>"`로 폐기한다. 파일은 남고 주입·검색에서 빠진다(`list --all`, `search --all`로 볼 수 있다). 파일을 직접 지우지 않는다(ID가 재사용되어 기존 참조가 다른 항목을 가리킬 수 있다).
- 삭제는 **사용자가 요청할 때만** 한다. `kn delete <id>`는 내용과 파일명의 slug를 지우고 ID만 남긴다(민감 정보가 들어간 경우 등). 방금 잘못 만든 항목이면 `kn delete <id> --purge`로 파일까지 지운다. 그 ID를 참조하는 기록이 있으면 거부되니, 참조를 정리하거나 `--purge` 없이 삭제한다. 출력의 `note`(동기화·백업의 버전 기록에는 남을 수 있음)를 사용자에게 전한다.
- 오타나 표현만 고치는 경우는 새 항목 없이 그 파일을 고친다(사본을 고쳐 `put`). 고치면서 코드와 대조해 확인했으면 `put --verified`(`kn verify`와 같은 효과).
- frontmatter는 CLI가 쓰므로 사본을 고쳐 put해도 반영되지 않는다. 제목·종류·`location`·`paths`·`tags`·`sources`는 `kn set <id>`로 바꾼다: `--title`, `--kind`, `--location`, 목록은 `--add-path`/`--remove-path`(`tag`·`source`도 같은 꼴, 반복 가능), 목록 전체를 바꿀 때만 `--paths "a/**,b/*.py"`. 제목·종류 변경은 오타·분류 수정용이고, 의미가 바뀌면 새 항목을 추가하고 supersede한다.

## 낡은 항목 점검 (doctor)

```
adesk doctor                            # 점검만 한다
adesk doctor --apply                    # 낡은 것으로 판정된 valid 항목을 stale로 표시한다
```
- 판정 기준: 확인(`verified`) 이후 `paths`를 바꾼 커밋이 3건 이상(`--min-commits`), `paths`에 해당하는 추적 파일이 없음, 본문이나 `location`이 참조하는 경로가 없음. 커밋은 현재 HEAD의 이력을 author 날짜로 판단하므로 rebase의 영향을 받지 않는다.
- 같이 점검하는 것: 동기화 충돌 사본, frontmatter 오류, ID 중복, 로컬에서 사라진 브랜치에 연결된 태스크, 30일 넘게 갱신되지 않은 태스크, 휴지통에 30일 넘게 있는 태스크(영구 삭제는 사용자가 동의할 때만).
- 세션 컨텍스트에 doctor 실행 안내가 있으면 사용자에게 한 줄로 실행을 제안한다. 실행하면 결과를 요약해 보여 주고, `--apply`는 사용자가 동의할 때만 실행한다.
- stale 항목을 한꺼번에 재확인할 필요는 없다. 해당 코드를 다룰 때(자동 주입에 "재확인 필요"로 나타날 때) 코드와 대조해 맞으면 `kn verify`, 틀리면 새 항목을 만들고 `kn supersede`한다.
