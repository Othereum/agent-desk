# agent-desk

**Claude Code가 어제 하던 일을 기억하게 하는 플러그인.**

진행상황, 결정, 발견을 태스크 단위로 기록해 맥락을 보존하고, 새 세션에서 그 일을 이어 가면 에이전트가 기록을 읽고 시작합니다.

- 새 세션마다 "어디까지 했고 왜 이렇게 했는지" 다시 설명하지 않아도 됩니다.
- 이미 기각한 대안을 에이전트가 다시 꺼내지 않습니다.
- 한 번 밟은 함정은 그 코드를 다시 열 때 자동으로 알려줍니다.

## 설치

> Python 3.11 이상과 git이 필요합니다.

```
claude plugin marketplace add Othereum/agent-desk
claude plugin install agent-desk@agent-desk
```

## 사용 방법

### 처음 쓰는 저장소

저장소마다 한 번 등록합니다. 등록하기 전에는 agent-desk가 아무것도 하지 않습니다.

```
나      이 저장소 agent-desk에 등록해줘.
Claude  프로젝트 key는 myapp, 태스크 ID는 기본 규칙(날짜-브랜치),
        main·develop은 공용 브랜치로 둘까요?
나      응
Claude  등록했습니다. 이제 이 저장소에서 하는 일을 태스크로 기록할 수 있습니다.
```

### 태스크 시작하기

할 일을 이야기하면 에이전트가 태스크로 기록할지 묻습니다. 처음 정한 목표와 범위가 태스크에 남아 며칠 뒤에도 같은 전제에서 이어 갑니다.

```
나      로그인 기능 만들 거야. 이번엔 이메일 로그인만 하고 소셜 로그인은 빼는걸로 하자.
Claude  태스크로 기록하면서 진행할까요? feature/login 브랜치를 만들어 연결하겠습니다.
나      응
Claude  태스크 261016-feature__login을 만들었습니다.
        목표: 이메일 로그인, 소셜 로그인은 범위 밖
```

### 방향을 정하면 결정으로 남기

함께 정한 방향은 기각한 대안과 이유까지 결정으로 남습니다. 나중에 같은 안이 다시 나와도 에이전트가 이미 검토한 것임을 압니다.

```
나      토큰 갱신은 만료 5분 전에 하자. 요청마다 검사하는 건 너무 무거워.
Claude  결정 D1로 기록했습니다.
        기각한 대안: 요청마다 만료 검사(모든 요청에 비용이 듦).
```

### 다음 날 이어서

새 세션에서 이어서 하자고 하면 에이전트가 태스크 기록을 읽고 시작합니다. 어제 일을 다시 설명하지 않아도 됩니다.

```
나      로그인 기능 작업 이어서 하자.
Claude  어제 로그인 API까지 끝났고, 다음 할 일은 토큰 갱신입니다.
        갱신은 만료 5분 전에 하기로 했으니(D1) 요청 경로에는 검사를 넣지 않겠습니다.
```

### 함정을 발견하면 지식으로

다른 태스크에서도 밟을 수 있는 함정이나 원인은 발견한 즉시 기록을 제안합니다. 기록한 지식은 나중에 다른 태스크에서 그 코드를 다룰 때 자동으로 나타납니다.

```
Claude  토큰이 가끔 두 번 발급되는 원인을 찾았습니다. 갱신 요청이 동시에 오면
        둘 다 만료 임박으로 판단합니다(src/auth/refresh.ts:42). 지식으로 남길까요?
나      응
Claude  K0012(함정)로 기록했습니다.

(몇 주 뒤, 다른 태스크에서)
나      비밀번호를 바꾸면 토큰을 새로 발급하게 해줘.
Claude  src/auth/refresh.ts에 관련 지식이 있습니다. K0012: 갱신 요청이 겹치면
        토큰이 두 번 발급됩니다. 재발급도 같은 잠금을 거치게 하겠습니다.
```

### 태스크 마치기

마칠 때 저장소 문서에 반영할 것이 남았는지 확인하고, 태스크가 끝나도 유효한 결정과 발견을 지식으로 옮겨 다음 작업에서도 보이게 합니다.

```
나      로그인 머지했어. 마무리하자.
Claude  마무리 전에 확인한 것이 두 가지 있습니다.
        - docs/auth.md에 토큰 갱신 시점이 빠져 있습니다. 추가할까요?
        - 결정 D1(갱신은 만료 5분 전)은 태스크가 끝나도 코드에 남는 사실이라
          지식으로 옮겨 두면 다음 작업에서도 보입니다.
나      둘 다 해줘
Claude  문서를 고치고 K0013으로 기록한 뒤 태스크를 완료로 아카이브했습니다.
```

## 핵심 개념

agent-desk가 관리하는 기록 전체를 **데스크**라고 부릅니다. 대화에서도 같은 이름으로 말하면 됩니다("데스크에 남겨줘", "데스크 점검해줘").

| 이름 | 가리키는 것 |
|---|---|
| 데스크 | agent-desk의 기록 전체 (태스크 기록 + 지식) |
| 태스크 기록 | 태스크 하나의 현황 · 결정 · 로그 |
| 현황 / 결정 / 로그 | state.md / decisions.md / log.md |
| 태스크 상태 | 예정 · 진행 중 · 보류 (열린 태스크), 완료 · 취소 (종료된 태스크, 아카이브로 이동) |
| 지식 | 코드에 대한 사실 항목. 일반적인 뜻과 구분할 때는 knowledge |
| 데스크 점검 | 낡은 지식, 충돌 사본, 방치된 태스크 찾기 (`doctor`) |

### 태스크(task)

태스크는 "로그인 기능 구현", "저장 버그 수정"처럼 하나의 목표를 가진 일이고, agent-desk의 기록은 모두 태스크 단위로 나뉘어 저장됩니다. 태스크마다 세 가지를 남깁니다. **지금 어디까지 했는지**(현황, state), **무엇을 왜 정했는지**(결정, decisions), **무엇을 알아냈는지**(로그, log)입니다.

세션에서 무슨 일을 할지는 사용자가 정합니다. 에이전트는 요청을 보고 그 태스크에 포커스를 두고, 그 세션의 기록은 포커스 태스크에만 쌓여 여러 일의 기록이 섞이지 않습니다. 포커스는 세션마다 따로 있어서 다른 세션에서 다른 일을 해도 섞이지 않습니다. 브랜치에 태스크를 연결해 두면 그 브랜치에서는 그 태스크가 기본값이 되어, 이 브랜치의 일을 하자고 하면 묻지 않고 포커스합니다. 브랜치 없이 `main`에서만 일한다면 브랜치 없는 태스크를 만들고, 이어서 할 태스크를 말하면 됩니다.

```
git 브랜치                 agent-desk 태스크
─────────────              ─────────────────────────────────────────────
feature/login   ───▶       tasks/261016-feature__login/
                             ├─ state.md       지금 어디까지, 다음에 할 일
                             ├─ decisions.md   무엇을 왜 정했나 (기각한 대안 포함)
                             └─ log.md         무엇을 알아냈나
fix/crash       ───▶       tasks/261016-fix__crash/
main            ···        브랜치 없는 태스크 (요청으로 골라 포커스)
```

### 지식(knowledge)

지식은 태스크가 끝나도 계속 유효한 **코드에 대한 사실**입니다. 태스크 기록이 "이 일을 어디까지 했나"라면, 지식은 "이 코드는 이렇다"입니다.

- 항목 하나에 사실 하나를 담습니다. 종류는 설계 결정(decision), 함정(pitfall), 원인이나 동작 방식(finding), 반복되는 절차(howto)입니다.
- 태스크가 아니라 **코드 경로**(`src/auth/**` 같은 glob)에 붙습니다. 그래서 어떤 태스크에서든 그 경로의 파일을 읽거나 고치면 자동으로 나타납니다.
- 프로젝트를 가리지 않는 사실(도구, OS, 셸 등)은 전역 지식으로 남기고, 필요할 때 검색으로 찾습니다.
- 주로 태스크를 마칠 때 추려 내지만, 함정이나 원인은 발견한 즉시 기록을 제안합니다.
- 코드가 바뀌어 낡은 항목은 데스크 점검(`doctor`)이 커밋 이력을 보고 찾아내 "재확인 필요"로 표시합니다.

### 기록이 가는 곳

```mermaid
flowchart LR
    W["`**작업 중 생긴 내용**`"] --> T["`**태스크 기록**
_진행 상황 · 결정_`"]
    W --> D["`**Claude Docs 설계 문서**
_태스크 단위 설계_`"]
    W --> R["`**저장소 문서**
_시스템의 현재 상태_`"]
    W --> K["`**지식**
_함정 · 원인 · 방법_`"]
```

설계 문서는 그 태스크가 진행된 시점의 판단을, 저장소 문서는 코드와 함께 고쳐지는 현재 상태를 담습니다. 어디에 둘지는 에이전트가 기준에 따라 제안하고 사용자가 승인합니다.

## 데이터 구조

데스크의 기록은 모두 사람이 읽고 고칠 수 있는 Markdown 파일이고, 플러그인과 분리된 데이터 폴더(`AGENT_DESK_ROOT`)에 쌓입니다.

```
<AGENT_DESK_ROOT>/
├─ desk.toml                          스키마 버전
├─ knowledge/G0001-*.md               전역 지식 (프로젝트 무관, 태그로 매칭)
└─ projects/<KEY>/                    저장소 하나 = 프로젝트 하나
    ├─ project.toml                   프로젝트 설정 (원격 URL, ID 규칙, 공용 브랜치)
    ├─ index.md                       태스크 목록 (자동 생성)
    ├─ tasks/<id>/                    열린 태스크(예정·진행 중·보류)
    │   ├─ state.md                     현황 (덮어씀)
    │   ├─ decisions.md                 결정 (항목 추가)
    │   └─ log.md                       로그 (덧붙이기만)
    ├─ archive/<id>/                  종료된 태스크
    ├─ trash/<id>/                    휴지통으로 옮긴 태스크 (되살릴 수 있음)
    └─ knowledge/K0001-*.md           프로젝트 지식 (경로 glob으로 매칭)
```

## 설정

### 데이터 폴더

환경 변수 `AGENT_DESK_ROOT`로 지정하고, 지정하지 않으면 `~/agent-desk`를 씁니다. `~/.claude/settings.json`의 `env`에 넣으면 Claude Code 세션에 적용됩니다.

```json
{ "env": { "AGENT_DESK_ROOT": "C:/Users/<you>/<동기화 폴더>/agent-desk" } }
```

클라우드 동기화 폴더에 두면 여러 PC에서 같은 기록을 쓸 수 있습니다.
- 폴더의 파일이 항상 로컬에 내려받아져 있도록(온디맨드 동기화 해제) 설정하세요. 그렇지 않으면 hook이 파일을 읽을 때 지연되거나 실패할 수 있습니다.
- 데이터 폴더 안에서 `git init`을 하지 마세요. 동기화 폴더 안의 `.git`은 손상되기 쉽습니다.
- 두 PC에서 같은 파일을 동시에 고쳐 충돌 사본이 생기면 세션 시작과 데스크 점검이 알려 줍니다.

### 저장소별 데이터 폴더

회사 일과 개인 프로젝트처럼 기록을 나누고 싶다면, 그 저장소의 `.claude/settings.local.json`에 `AGENT_DESK_ROOT`를 넣습니다. 그 저장소에서 연 세션에서는 이 값이 사용자 설정을 덮어씁니다. 개인 경로가 들어가므로 이 파일은 커밋하지 마세요.

```json
{ "env": { "AGENT_DESK_ROOT": "C:/Users/<you>/<개인 동기화 폴더>/agent-desk" } }
```

## 더 알아보기

세부 동작과 규칙은 에이전트가 따르는 스킬에 있습니다.

- [설계 원칙](docs/design-principles.md): 기능과 동작을 정할 때 지키는 기본 원칙
- [`desk`](skills/desk/SKILL.md): 용어, 태스크 생성 기준, 기록 규칙, 세션의 태스크와 상위 태스크, 문서 위치 기준
- [`kn`](skills/kn/SKILL.md): 지식 형식, 기록·수정 규칙, 데스크 점검
- [`desk-new`](skills/desk-new/SKILL.md) · [`desk-close`](skills/desk-close/SKILL.md) · [`desk-init`](skills/desk-init/SKILL.md): 절차
- CLI: `python bin/desk.py --help`. Claude Code의 셸 도구(Bash, PowerShell)에서는 플러그인 `bin/`이 PATH에 들어가므로 `adesk --help`로 실행할 수 있습니다.
- 테스트: `python -m unittest discover -s tests`
