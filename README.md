# agent-desk

**Claude Code가 어제 하던 일을 기억하게 하는 플러그인.**

진행상황, 결정, 발견을 태스크 단위로 기록해 맥락을 보존하고, 새 세션에서 그 일을 이어 가면 에이전트가 기록을 읽고 시작합니다. "어디까지 했고 왜 이렇게 했는지" 다시 설명하지 않아도 됩니다.

## 설치

> Python 3.11 이상과 git이 필요합니다.

```
claude plugin marketplace add Othereum/agent-desk
claude plugin install agent-desk@agent-desk
```

## 사용 방법

### 처음 쓰는 저장소

저장소마다 한 번, 기록을 둘 데스크 폴더를 정해 등록합니다. 등록하기 전에는 agent-desk가 아무것도 하지 않습니다.

```
나      이 저장소를 agent-desk에 등록해줘.
Claude  데스크 폴더를 어디에 둘까요? 다른 저장소의 데스크 옆인
        C:/Users/me/Sync/agent-desk/myapp 을 제안합니다.
나      응
Claude  등록했습니다. 이제 이 저장소에서 하는 일을 태스크로 기록할 수 있습니다.
```

### 태스크 시작하기

할 일을 이야기하면 에이전트가 태스크로 기록할지 묻습니다. 처음 정한 목표와 범위가 태스크에 남아 며칠 뒤에도 같은 전제에서 이어 갑니다.

```
나      로그인 기능 만들 거야. 이번엔 이메일 로그인만 하고 소셜 로그인은 빼는걸로 하자.
Claude  태스크로 기록하면서 진행할까요?
나      응
Claude  태스크 261016-login을 만들어 지금 브랜치(feature/login)에 연결했습니다.
        목표: 이메일 로그인, 소셜 로그인은 범위 밖
```

### 방향을 정하면 결정으로 남기

함께 정한 방향은 기각한 대안과 이유까지 결정으로 남습니다. 나중에 같은 안이 다시 나와도 에이전트가 이미 검토한 것임을 압니다.

```
나      토큰 갱신은 만료 5분 전에 하자. 요청마다 검사하는 건 너무 무거워.
Claude  결정 D1로 기록했습니다.
        기각한 대안: 요청마다 만료 검사(모든 요청에 비용이 듦).
```

### 다음 날 이어서

새 세션에서 이어서 하자고 하면 에이전트가 태스크 기록을 읽고 시작합니다. 어제 일을 다시 설명하지 않아도 됩니다.

```
나      로그인 기능 작업 이어서 하자.
Claude  어제 로그인 API까지 끝났고, 다음 할 일은 토큰 갱신입니다.
        갱신은 만료 5분 전에 하기로 했으니(D1) 요청 경로에는 검사를 넣지 않겠습니다.
```

### 태스크 마치기

마칠 때 현황에 최종 결과를 남기고 완료로 표시합니다. 결정은 태스크와 함께 남아, 나중에 그 설계를 바꾸려 할 때 찾아볼 수 있습니다.

```
나      로그인 머지했어. 마무리하자.
Claude  현황에 최종 결과(이메일 로그인, 만료 5분 전 갱신)를 적고
        태스크를 완료로 표시했습니다.
```

## 핵심 개념

agent-desk가 관리하는 기록 공간을 **데스크**라고 부릅니다.

| 이름 | 가리키는 것 |
|---|---|
| 데스크 | agent-desk의 기록 공간 (저장소마다 데스크 폴더 하나) |
| 태스크 기록 | 태스크 하나의 현황 · 결정 · 로그 |
| 현황 / 결정 / 로그 | state.md / decisions.md / log.md |
| 첨부파일 | 태스크에 붙여 둔 파일 (files/) |
| 태스크 상태 | 예정 · 진행 중 · 보류 (열린 태스크), 완료 · 취소 (종료된 태스크) |
| 데스크 점검 | 충돌 사본, 읽을 수 없는 기록, 방치된 태스크 찾기 |

### 태스크(task)

태스크는 "로그인 기능 구현", "저장 버그 수정"처럼 하나의 목표를 가진 일이고, agent-desk의 기록은 모두 태스크 단위로 나뉘어 저장됩니다. 태스크마다 세 가지를 남깁니다. **지금 어디까지 했는지**(현황, state), **무엇을 왜 정했는지**(결정, decisions), **무엇을 알아냈는지**(로그, log)입니다.

세션을 시작하면 에이전트는 열린 태스크 목록을 받습니다. 무슨 일을 할지는 사용자가 정하고, 에이전트는 그 태스크의 기록을 읽고 시작해 그 태스크에 기록합니다. 브랜치에 태스크를 연결해 두면 목록에 표시되어, 이 브랜치의 일을 하자고 하면 묻지 않고 그 태스크로 시작합니다. 브랜치 없이 `main`에서만 일한다면 브랜치 없는 태스크를 만들고, 이어서 할 태스크를 말하면 됩니다.

```
git 브랜치                 agent-desk 태스크
─────────────              ─────────────────────────────────────────────
feature/login   ───▶       261016-login/
                             ├─ state.md       지금 어디까지, 다음에 할 일
                             ├─ decisions.md   무엇을 왜 정했나 (기각한 대안 포함)
                             └─ log.md         무엇을 알아냈나
fix/crash       ───▶       261016-crash-on-save/
main            ···        브랜치 없는 태스크 (요청으로 골라 시작)
```

## 데이터 구조

데스크의 기록은 모두 사람이 읽고 고칠 수 있는 Markdown 파일이고, 저장소 밖의 데스크 폴더에 쌓입니다. 에이전트는 이 파일을 기본 파일 도구로 직접 읽고 고칩니다.

```
<데스크 폴더>/
└─ <id>/                  태스크 하나 (열린 태스크와 종료된 태스크 모두)
    ├─ state.md             현황 (고쳐 씀, frontmatter: 제목 · 상태 · 상위 태스크 · 브랜치)
    ├─ decisions.md         결정 (항목 추가)
    ├─ log.md               로그 (덧붙이기만)
    └─ files/               첨부파일
```

## 설정

### 데스크 폴더

등록은 저장소의 git 설정에 데스크 폴더 경로를 적는 것입니다. 에이전트에게 등록을 요청하면 대신 해 줍니다. worktree도 같은 설정을 씁니다.

```
git config agent-desk.dir "C:/Users/<you>/<동기화 폴더>/agent-desk/myapp"
```

클라우드 동기화 폴더에 두면 여러 PC에서 같은 기록을 쓸 수 있으므로 추천합니다. 다른 PC의 클론도 같은 폴더로 등록하면 됩니다.
- 폴더의 파일이 항상 로컬에 내려받아져 있도록 설정하세요. 그렇지 않으면 파일을 읽을 때 지연되거나 실패할 수 있습니다.
- 두 PC에서 같은 파일을 동시에 고쳐 충돌 사본이 생기면 세션 시작이 알려 줍니다.

### 이전 버전에서 올라올 때

0.12.x까지의 데이터(`AGENT_DESK_ROOT` 데이터 루트)는 세션 시작이 알아보고 변환을 안내합니다. `adesk migrate`는 태스크 폴더를 새 구조로 옮기고, 이 PC에서 등록했던 저장소를 git 설정으로 등록합니다(`--dry-run`으로 미리 보기).
