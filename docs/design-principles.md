# 설계 원칙

agent-desk의 기능과 동작을 정할 때 지키는 기본 원칙입니다. 개별 설계 결정은 이 원칙을 구체적인 상황에 적용한 것입니다. 기능을 추가하거나 동작을 바꿀 때, 그리고 어느 쪽으로 정할지 판단이 갈릴 때 이 문서를 봅니다.

## 1. 태스크 단위 맥락 보존만 한다

agent-desk는 태스크 하나의 맥락(목표, 진행, 결정, 알아낸 것)을 세션을 넘어 남기고 다시 꺼내 주는 일만 합니다. 기록 밖의 산출물이나 개발 흐름은 다루지 않습니다.

- 태스크가 끝나도 유효한 사실, 사용자와 일하는 방식, 시스템 문서는 데스크에 두지 않습니다. 어디에 둘지는 Claude Code와 프로젝트 지침이 정합니다.
- 저장소 문서·설계 문서를 언제 만들고 고칠지, 브랜치를 언제 만들고 병합할지는 정하지 않습니다. 그런 흐름이 태스크 기록을 읽어 쓰도록 기록을 남기는 데까지만 합니다.
- 새 기능은 태스크 맥락을 남기거나, 다시 꺼내거나, 그 기록을 지키는 일일 때만 넣습니다.

## 2. 대화로 쓴다

사용자는 말로 요청하고 에이전트가 처리합니다. 명령어를 알아야만 쓸 수 있는 기능은 만들지 않습니다.

- 사용자와 에이전트가 같은 용어를 씁니다. 짧게 부르고, 문맥으로 해석하고, 모호하면 한 줄로 묻습니다.
- CLI(`adesk`)를 쓰는 쪽은 에이전트입니다. 에이전트는 사용법을 읽기 전에 익숙한 관례부터 쓰므로, git·gh 같은 관례로 추측해 썼을 때 그대로 동작하게 만듭니다. 관례를 벗어나야 하면 조용히 엉뚱한 결과를 내지 말고 고칠 방법을 알려 주는 오류를 냅니다.
- README "사용 방법"의 대화 예시는 이 원칙을 보여 주는 핵심 장면입니다.

## 3. 확정은 사용자가 한다

에이전트와 hook은 감지하고 추천하는 데까지만 합니다. 무엇을 기록하고, 어느 태스크에서 일하고, 무엇을 지우거나 한꺼번에 바꿀지는 사용자의 요청이나 동의로 정합니다.

- 세션 시작은 이어 갈 태스크의 후보만 알리고, 포커스는 사용자의 요청을 보고 정합니다.
- 새 일을 시작하거나 새 브랜치를 만들면 태스크로 기록할지 묻습니다.
- 데스크 점검의 정리(`doctor --apply`)와 삭제는 사용자가 동의하거나 요청할 때만 합니다.

## 4. 판단은 에이전트, 결정론은 CLI

글과 판단은 에이전트가 맡고, 틀리면 안 되는 일(ID 발급, 상태 전환, 이동, 메타데이터)은 CLI가 맡습니다.

- frontmatter는 CLI만 씁니다. 에이전트가 바꿔야 하는 값은 전용 명령(`set`, `status`, `link` 등)으로 바꿉니다.
- 현황·결정·로그의 본문은 에이전트의 글입니다. CLI는 글의 구조를 만들거나 고치지 않습니다.
- 기계가 판단에 쓰는 값은 frontmatter에 두고 글에서 읽어 내지 않습니다. 글을 파싱하는 코드를 넣으려면 그 값을 frontmatter로 옮길 수 없는지 먼저 봅니다. 남겨 두는 휴리스틱은 틀려도 결과가 무해한 것만 둡니다.

## 5. 컨텍스트는 비싸다

에이전트의 컨텍스트에는 필요한 것만, 필요할 때, 한 번 넣습니다.

- 세션 주입은 짧게 유지합니다. 문구를 더할 때는 한 줄로 끝낼 수 있는지 먼저 보고, 설명·이유·예외 상황의 대처는 스킬에 둡니다.
- 세션 시작은 태스크 후보만 알리고, 기록 전체는 포커스한 태스크에만 넣습니다. 로그는 에이전트가 필요할 때 찾아 읽습니다.
- hook은 도구를 호출할 때마다 실행되므로 시작 비용과 실행 시간을 아낍니다. 무거운 import, 잠금 대기, 불필요한 git 호출을 hook 경로에 넣지 않습니다.

## 6. 기록은 잃지 않는다

데스크의 기록은 사람이 읽고 고칠 수 있는 파일이고, 플러그인 코드와 따로 삽니다. 어떤 상황에서도 기록이 조용히 사라지거나 어긋나지 않게 합니다.

- 틀리거나 낡은 것은 지우지 않고 대체합니다. 결정은 대체를 표시하고, 로그는 덧붙이기만 합니다. 태스크 삭제는 휴지통으로 옮기는 것이 기본입니다.
- ID는 만든 뒤 바꾸지 않고 재사용하지 않습니다. 다른 기록이 참조하는 항목은 지울 수 없습니다.
- 여러 에이전트와 hook이 동시에 실행돼도 기록이 깨지지 않게 합니다. 데이터를 바꾸는 CLI 명령은 잠금을 잡고, 파일은 원자적으로 교체합니다. 새 명령도 기본으로 보호받는 구조로 만듭니다.
- 데이터 형식은 플러그인 버전과 따로 관리합니다(`desk.toml` 스키마 버전). 형식이 바뀌어도 hook은 이전 데이터를 읽어 동작하고, 기록을 바꾸는 명령은 migrate 뒤에만 허용합니다.
- 데스크 파일은 Edit/Write 대신 CLI(`put`·`append`)로 씁니다. 대화 되감기가 CLI 변경과 어긋난 데스크를 남기지 않게 하기 위해서입니다.

## 7. 데스크는 저장소 밖의 로컬 기록이다

데스크는 사용자 한 사람의 로컬 환경에 있는 기록이고 저장소와 함께 배포되지 않습니다. 저장소의 코드·테스트·문서·주석·커밋 메시지는 데스크를 볼 수 없는 사람도 이해할 수 있어야 합니다.

- 저장소 산출물은 태스크 ID, 결정 번호, 데스크 경로를 근거로 가리키지 않습니다. 근거는 그 자리에 풀어 씁니다.
- 이 경계는 agent-desk를 쓰는 사용자의 프로젝트에도 같습니다. 그래서 스킬이 에이전트에게 지키게 합니다.
