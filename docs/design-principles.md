# 설계 원칙

agent-desk의 기능과 동작을 정할 때, 판단이 갈릴 때 보는 원칙입니다.

## 1. 태스크 기록만 한다

태스크 단위로 일의 맥락을 남겨 다음 세션이 이어 가게 하는 것이 전부입니다. 태스크가 아닌 것, 기록이 아닌 일(작업 흐름 관리 등)은 하지 않습니다. 무엇을 기록하고 어느 태스크를 할지는 사용자가 정합니다.

## 2. 단순함이 우선이다

보장을 하나 더 얻는 것보다 구조가 단순한 쪽을 고릅니다. 문제가 생기면 장치를 더하기 전에 원인이 된 장치를 없앨 수 있는지 봅니다. Claude Code나 git이 하는 일은 다시 만들지 않고, 같은 사실을 두 곳에 두지 않으며, 드문 문제는 겪은 뒤에 대응합니다.

## 3. 에이전트에게 맡긴다

데스크는 평범한 Markdown 폴더이고 에이전트가 판단해서 읽고 고칩니다. 전용 명령을 두지 않고, 사용자는 말로 요청합니다. 스킬에는 에이전트가 알 수 없는 것과 어기면 기록의 가치가 사라지는 규칙만 둡니다.

## 4. 컨텍스트와 대기 시간은 비싸다

세션 시작에 열린 태스크 목록만 짧게 넣고, 그 밖의 hook은 두지 않습니다. 경고에 대처하는 법은 경고 메시지에 적습니다.

## 5. 기록은 잃지 않는다

기록의 주인은 사용자입니다. 낡은 기록은 지우지 않고 대체하며, 지우는 일은 사용자가 요청할 때만 합니다. 읽을 수 없는 기록과 이전 형식은 세션 시작이 알립니다.

## 6. 저장소는 데스크 없이 읽혀야 한다

데스크는 사용자 한 사람의 기록이므로, 저장소 산출물(코드, 문서, 커밋 메시지)에서 데스크를 근거로 가리키지 않습니다.
