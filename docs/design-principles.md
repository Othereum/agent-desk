# 설계 원칙

agent-desk의 기능과 동작을 정할 때 지키는 기본 원칙입니다. 기능을 추가하거나 동작을 바꿀 때, 그리고 어느 쪽으로 정할지 판단이 갈릴 때 이 문서를 봅니다. 각 장의 본문은 원칙과 그 이유이고, 글머리표는 그 원칙에서 나온 규칙입니다. 여기에 기능 명세는 적지 않습니다.

## 1. agent-desk는 태스크 기록 도구다

agent-desk는 태스크 단위로 일의 기록을 남기고, 다음 세션에 다시 꺼내 주는 도구입니다. 모든 것은 태스크를 기반으로 합니다. 기능을 넣을지는 이 정체성 안의 일인지로 판단합니다.

- 태스크에 속하지 않는 것은 데스크에 두지 않습니다.
- 무엇을 태스크로 남길지는 사용자가 정합니다. 브랜치나 세션이 생겼다고 태스크를 저절로 만들지 않습니다.
- 기록이 아닌 일은 하지 않습니다. 문서를 언제 고치고 브랜치를 언제 만들고 병합할지는 정하지 않고, 그 흐름이 읽을 기록을 남기는 데까지만 합니다.

## 2. 대화로 쓴다

사용자는 말로 요청하고 에이전트가 처리합니다. 명령어를 알아야만 쓸 수 있는 기능은 만들지 않습니다.

- 사용자와 에이전트가 같은 용어를 씁니다.
- CLI(`adesk`)를 쓰는 쪽은 에이전트입니다. 에이전트는 사용법을 읽기 전에 익숙한 관례부터 쓰므로, 관례로 추측해 썼을 때 그대로 동작하게 만듭니다.

## 3. 판단은 에이전트, 결정론은 CLI

글과 판단은 에이전트가 맡고, 틀리면 안 되는 일(ID 발급, 상태 전환, 이동, 메타데이터)은 CLI가 맡습니다.

- 데스크에 쓰는 일은 모두 CLI를 거칩니다. 에이전트는 데스크 파일을 Edit/Write로 직접 고치지 않습니다. frontmatter는 전용 명령(`set`, `status`, `link` 등)으로, 본문은 `put`·`append`·`log`로 씁니다. 그래야 모든 쓰기가 잠금과 원자적 교체를 거치고, 대화를 되감아도 CLI 변경과 어긋난 데스크가 남지 않습니다.
- 현황·결정·로그의 본문은 에이전트가 쓰는 글입니다. CLI는 글의 구조를 만들거나 고치지 않습니다.
- 프로그램이 판단에 쓰는 값은 frontmatter에 두고 글에서 읽어 내지 않습니다. 글을 파싱하는 코드를 넣으려면 그 값을 frontmatter로 옮길 수 없는지 먼저 봅니다. 그래도 남기는 휴리스틱은 틀려도 결과가 무해한 것만 둡니다.

## 4. 컨텍스트와 대기 시간은 비싸다

에이전트의 컨텍스트에는 필요한 것만, 필요할 때, 한 번 넣습니다. hook은 사용자가 작업하는 도중에 실행되므로 사용자를 기다리게 하지 않습니다.

- 세션 주입은 짧게 유지합니다. 문구를 더할 때는 한 줄로 끝낼 수 있는지 먼저 보고, 설명·이유·예외 상황의 대처는 스킬에 둡니다.
- CLI 출력(오류·경고 메시지)으로 알 수 있는 내용은 스킬에 적지 않습니다. 오류나 경고가 났을 때 할 일은 그 메시지에 적어서, 그 상황이 생겼을 때만 컨텍스트에 들어가게 합니다.
- 기록 전체는 포커스한 태스크에만 넣습니다. 로그처럼 계속 길어지는 기록은 넣지 않고, 에이전트가 필요할 때 찾아 읽게 합니다.
- hook은 프롬프트를 보낼 때마다, 파일을 고칠 때마다 실행되므로 시작 비용과 실행 시간을 아낍니다. 무거운 import, 잠금 대기, 불필요한 git 호출을 hook 경로에 넣지 않습니다.

## 5. 기록은 잃지 않는다

데스크의 기록은 사람이 읽고 고칠 수 있는 파일이고, 플러그인 코드와 따로 보관됩니다. 어떤 상황에서도 기록이 조용히 사라지거나 어긋나지 않게 합니다.

- 기록한 글은 틀리거나 낡아도 지우지 않고 대체합니다. 결정은 대체됐다고 표시하고, 로그는 덧붙이기만 합니다. 태스크를 삭제하면 기본으로 휴지통으로 옮깁니다.
- 기록의 주인은 사용자입니다. 위 규칙은 에이전트가 스스로 할 때의 것이고, 사용자가 지우라고 하거나 직접 지운 기록은 지운 상태를 정상으로 봅니다. 에이전트가 쓰다가 기록을 실수로 빠뜨린 것은 CLI가 알립니다.
- 첨부파일은 기록한 글이 아니라 참고 자료이므로 교체하거나 지울 수 있습니다. 대신 교체하거나 지웠다는 사실을 로그에 남깁니다.
- ID는 만든 뒤 바꾸지 않고 재사용하지 않습니다. 다른 기록이 참조하는 항목은 지울 수 없습니다.
- 에이전트 여러 개와 hook이 동시에 실행돼도 기록이 깨지지 않게 합니다. 데이터를 바꾸는 CLI 명령은 잠금을 잡고, 파일은 원자적으로 교체합니다. 새 명령도 따로 신경 쓰지 않아도 보호받는 구조로 만듭니다.
- 데이터 형식은 플러그인 버전과 따로 관리합니다(`desk.toml` 스키마 버전). 형식이 바뀌어도 hook은 이전 데이터를 읽어 동작하고, 기록을 바꾸는 명령은 migrate한 뒤에만 허용합니다.

## 6. 저장소는 데스크 없이 읽혀야 한다

데스크는 사용자 한 사람의 로컬 기록이고 저장소와 함께 배포되지 않습니다. 그래서 저장소의 코드·테스트·문서·주석·커밋 메시지는 데스크를 볼 수 없는 사람도 이해할 수 있어야 합니다.

- 저장소 산출물은 태스크 ID, 결정 번호, 데스크 경로를 근거로 가리키지 않습니다. 근거는 그 자리에 풀어 씁니다.
- agent-desk를 쓰는 사용자의 프로젝트에도 똑같이 적용됩니다.
